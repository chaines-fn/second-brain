## Objective 1: Increase engineering velocity through an AI-DLC

Build a repo scorecard (DX metrics) plus a repeatable repo-readiness playbook, applied through an **embed model**: the team parachutes into specific engineering teams to make their repos more AI-native. Goal: the top 10 most-committed-to repos fully AI-enabled by end of Q3, with embeds producing both quantitative metrics and qualitative engineer feedback on whether the changes actually help.

**Motivating number:** a ~36-hour average wait from "PR ready to merge" to actual merge is the core data point driving this objective.

**Technical grounding (from research):**
- AWS Bedrock AgentCore reached general availability at the end of April 2026.
- Agents are commonly defined/versioned/deployed via **AWS CDK**. Terraform support is listed by AWS as "coming soon," so M2's "IaC modules" most likely means CDK constructs (model selection, tool config, session policy, permissions, all as code).
- FN's CI/CD runs through **Harness**, not GitHub Actions, confirmed. The exact mechanics of how Harness triggers the AWS-side CDK deploy will get concrete during M2/M3 build-out.
- AgentCore Runtime is framework-agnostic (LangChain, LangGraph, Strands Agents, AutoGen, etc.), consistent with FN's own LangGraph direction.

**Test bed:** Op Cop, Joe's existing production-incident-diagnosis agent (Datadog/logs-based), is the first long-running agent case. Success is measured by MTTR reduction, faster diagnosis, and fewer manual investigations, not just "agent deployed."

**Future agent prioritization beyond Op Cop:** feasibility + engineering-hours-saved + incident-reduction, ideally owned by platform engineering once bandwidth allows (it doesn't today).
