# UI Modernization — Overview

**Last updated:** 2026-11-09

## What Is This Project?

UI Modernization is a multi-track initiative to modernize Field Nation's web frontend. The existing UI is a monolithic service dating back to 2008, carrying legacy jQuery, Angular, and outdated React patterns that result in 5-10 second page loads, hours-long deploy times, and significant security vulnerabilities from end-of-life libraries.

Rather than a wholesale rewrite, the approach uses a **strangler pattern** — incrementally migrating pages into a modern mono-repo ("Core-UI") while the legacy UI continues to serve unconverted routes. The goal is to get 90%+ of web traffic (happy path) onto an elevated experience that's faster to build on, test, and more responsive for customers.

## Goals

- **Performance:** Reduce largest contentful paint (LCP) from 5-10s to 2-3s via SPA routing and eliminating the UI service middleware from the critical path
- **Deploy speed:** Get build/deploy/rollback under 10 minutes (currently takes hours)
- **Developer experience:** Standardize on modern React (TypeScript, hooks, tests, docs), eliminate duplicative libraries (3 rich text editors, 3 charting libs, 3 date/time libs, etc.)
- **Security:** Remove 14-year-old jQuery and other EOL libraries with known exploits
- **Adopt systems:** Leverage MUI as the component library and Vite/Vitest as the build/test toolchain instead of homegrown solutions

## Tracks

1. **Track 1 — Flightboard:** Establish SPA groundwork, break Flightboard off the UI service, modernize builds, convert datagrid/navigation, convert Flightboard components
2. **Track 2 — Single Process for Building UIs:** Standardize on Core-UI as the one path for new frontend work (with a micro-frontend exception case requiring pre-approval)
3. **Track 3 — Work Order Detail:** Convert the most popular page, fold in Provider Match, complete the Flightboard → WOD → Match SPA flow
4. **Track 4 — User Profile:** Expand the framework to federated UIs, complete the 4 pages that make up 90%+ of web traffic
5. **Track 5 — Lift/Deprecate Classic Pages:** Retire legacy Angular and classic pages, address security and maintenance burden
