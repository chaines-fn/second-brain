# UI Modernization — Tech Context

*Relevant technical background for this project.*

## Tech Stack

### Legacy (being migrated away from)
| Technology | Role | Issue |
|---|---|---|
| jQuery (14 years old) | DOM manipulation, legacy pages | Known XSS/security exploits, EOL |
| Angular (classic) | Some legacy pages | Deprecated, mixed with other frameworks |
| Webpack (DLL-based, 2016 config) | Build tooling | Hours-long builds, polyfills for dead browsers (IE 8/Vista era) |
| Gulp, Grunt | Legacy build systems | Developer confusion when debugging legacy pages |
| Prototype.js, Scriptaculus, Handlebars | Various legacy | EOL, monkey-patched preventing updates |
| 3x duplicated libraries | Rich text, charting, date/time | Dependency sprawl, maintenance burden |

### Target (Core-UI)
| Technology | Role |
|---|---|
| React (modern — TypeScript, hooks) | UI framework |
| MUI (Material UI) | Component library — standardizing all components here |
| Vite | Build tooling — fast, modern-browser-native |
| Vitest | Unit test runner — concurrent, fast |
| Storybook | Component documentation and development |
| Mono-repo (Core-UI) | Single destination repo with namespaced packages per team/domain |

### Infrastructure
| Technology | Role |
|---|---|
| Kubernetes (16 pods for UI service currently) | Hosting |
| AES (API/Edge Service) | Gateway — handles auth, session, routing |
| Cloudflare / CloudFront | CDN, CORS, static asset hosting |
| S3 | Static asset storage for SPA |
| Tilt | Local dev environment (replacing docker-compose) |

## Key Technical Implications

- **SPA Router is the architectural linchpin.** Pages are migrated one at a time into the Core-UI SPA router. AES routes converted pages directly to static assets, bypassing the UI service entirely. This is what delivers the 2-3x LCP improvement.
- **UI service middleware is being eliminated for converted pages.** Session management, IA, contracts, and user context move into browser-cached hooks. IP blocking goes to AES/Cloudflare. This removes the serial middleware chain that adds 5-10s overhead.
- **"Acting as" / partner functionality** is a known hurdle — users who impersonate other users may need to stay in the full-page-load path unless addressed in AES.
- **Core-UI is the one recommended path** for new frontend work. Micro-frontends require pre-approval and a TDR. This is a deliberate consolidation to reduce the current 4-5 different strategies.
